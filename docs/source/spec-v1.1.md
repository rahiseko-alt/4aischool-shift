## 1. 目的と判定範囲

学生が翌月のアルバイト予定シフトを1ページで入力し、月末に実績を確認する。アプリは資格外活動の時間制限と機械的に判定できる労働条件違反を確定前に止め、学校は全学生の状況を管理画面で把握・印刷する。

- 対象：在留資格「留学」で在籍する専修学校の学生。約200名、毎年約100名入替。
- 保存：提出対象月から最低24か月。
- 運営費：Googleへの支払い0円。
- 判定するもの：資格外活動28時間、長期休業1日8時間、深夜割増計算、最低賃金、18歳未満の制限、勤務先の可否。
- 判定しないもの：36協定、変形労働時間制、法定休日、就業規則、実際に取得した休憩、実際に支払われた賃金。
- 表示しないもの：「法律上問題ありません」。最終表示は「確定済み」のみ。

文科省は専修学校に対し、3か月に1度、①資格外活動許可の有無②就業先名称③具体的な就業内容④毎日の就業時間を正確に把握するよう求めている。EduSurveyの報告項目も「毎日の就業時間の実態」を問う。予定だけでは要件を満たさないため、v1.1で実績確認を加える。

## 2. 法令・許可条件

包括的な資格外活動許可の条件は次のとおり（入管法施行規則19条5項1号）。

| 条件 | 内容 | 根拠 |
| --- | --- | --- |
| 通常期間 | 1週28時間以内 | 施行規則19条5項1号、入管庁Q&A Q65 |
| 学則で定める長期休業期間 | 1日8時間以内 | 同上 |
| 週の数え方 | どの曜日から起算しても7日間で28時間以内 | 入管庁Q&A（令和8年5月19日）Q9 |
| 複数勤務先 | 全勤務先を合算 | 入管庁Q&A Q9 |
| 就業場所 | 風俗営業・性風俗関連特殊営業等が営まれる場所は不可 | 施行規則19条5項1号 |
| 期間 | 教育機関に在籍している間に限る | 同上 |

注記：Q9は日本語教育機関向けQ&Aであり、専修学校を名宛にした明文ではない【曖昧】。判定方式として採用する。「特定遊興飲食店営業」の除外は施行規則の現行条文で要確認【曖昧】。

学生マスタに保持する項目：

- 資格外活動許可：あり／なし
- 許可確認日、許可期限（在留期限と同日）
- 在籍状態：在籍／休学／卒業／退学

許可なし・期限切れ・在籍対象外は確定不可。休学中の可否は入管庁の「在籍中」の解釈に依存するため、学校の学則判断で設定可能とする【曖昧】。既定値は「休学＝確定不可」。

## 3. 時間計算の共通ルール

すべての判定はサーバ側で分単位に変換してから行う。

- 時刻は15分単位で入力（00・15・30・45）。
- 1日に複数シフトを登録できる。同日内の重複は保存不可。
- 終了時刻が開始時刻以下なら翌日終了とみなす（例 22:00〜02:00＝240分）。
- 帰属日は開始日。ローリング7日・長期休業1日8h・18歳未満判定はすべて開始日に帰属させる。
- 1シフトの拘束時間は最大16時間。超過は入力エラー。
- 実労働分＝拘束分−自動休憩分。
- 深夜分＝実労働のうち22:00〜翌05:00に含まれる分。休憩は勤務中央に置くため深夜分は休憩位置を考慮して計算する。

## 4. 週28時間ローリング7日判定

月曜〜日曜の固定集計は禁止する。毎日について、その日から6日後までの7日間の実労働分合計を計算する。

```
rolling7(D) = Σ_{d=D}^{D+6} work(d) ≤ 1680
```

1,680分＝28時間。全勤務先を合算する。

月またぎ：

- 前月の最終6日と翌月の最初6日を必ず参照する。
- 前月は「確定済」データのみ使う。前月が下書き・未提出なら0分として計算し、画面に「前月未確定」を表示する。
- 翌月は通常未入力なので0分。翌月入力時に前月確定データで再検算される。

判定対象は「予定」と「実績」の両方。実績が入力された日は実績分で再計算する。

## 5. 長期休業

長期休業は学校管理者だけが登録する。学則で定める期間のみが対象で、土日・祝日・休講日は対象にしない。

| 項目 | 例 |
| --- | --- |
| 名称 | 冬季休業 |
| 開始 | 2026/12/24 |
| 終了 | 2027/01/07 |
| 年度 | 2026 |

判定：長期休業日の実労働分 ≤ 480分（8時間）。超過は「8時間超過」で確定不可。

学生画面では該当日の行全体を赤枠にし、「長期休暇」とだけ表示する。説明文は出さない。

通常期間と長期休業期間が混在する7日間の計算方法は公的資料に明文がない。本システムは安全側に倒し、7日間すべてが長期休業日になるまで28時間検算を維持する。これは法律ではなく学校の安全運用ルールである。

## 6. 休憩の自動入力

学生は休憩時間を入力しない。開始・終了の拘束時間から自動生成する。

| 拘束時間 | 自動休憩 |
| --- | --- |
| 6時間以下 | 0分 |
| 6時間超〜8時間以下 | 45分 |
| 8時間超 | 60分 |

労基法34条は労働時間6時間超で45分、8時間超で60分の休憩を求める。本アプリは安全側に倒し、拘束時間を基準にする。このため拘束8時間15分は休憩60分・実働7時間15分となり、給与概算は実態より低めに出ることがある。

休憩の位置は勤務時間の中央付近に置き、15分単位に丸める。例：09:00〜18:00は13:00〜14:00。内部で休憩開始・終了を保持し、深夜分の計算に使う。学生画面には「休憩 60分」だけ表示する。

## 7. 深夜・早朝・給与概算

深夜は22:00〜翌05:00。この時間帯は25%以上の割増が必要（労基法37条）。

```
予定給与 = 時給 × 実働分/60 + 時給 × 0.25 × 深夜分/60 + 早朝手当
```

例：時給1,200円、18:00〜23:00、実働5時間、深夜1時間。通常6,000円＋深夜加算300円＝6,300円。

早朝割増は法定ではない。勤務先ごとに「なし」または「05:00〜08:00 +100円/時間」のように任意設定し、未設定なら0円。

給与は予定シフト上の概算であり、実際の支払額を保証しない。

## 8. 最低賃金

勤務先登録時に都道府県と基本時給を登録し、地域別最低賃金と比較する。時給が適用最低賃金未満なら「時給不足」で確定不可。

MINIMUM_WAGE_MASTER：

| 列 | 内容 |
| --- | --- |
| prefecture | 都道府県 |
| amount | 金額（円） |
| effective_from | 発効日 |
| effective_to | 終了日 |

判定はシフトの各日付に対して、その日に有効な金額で行う。同一月内で発効日をまたぐ場合は日ごとに判定する。

運用ルール：

- 発効日は都道府県ごとに異なる（2025年度改定は2025年10月〜2026年3月に分散）。管理者は毎年8月の答申後と10月に、厚労省「地域別最低賃金の全国一覧」で全都道府県を点検する。
- 特定（産業別）最低賃金は自由記述の仕事内容から自動判定できないため、本アプリは地域別のみを判定する。産業別が高い勤務先は管理者が手動で確認する。
- 2026年度改定の発効日は未確認【曖昧】。稼働前に最新一覧で更新する。

## 9. 勤務先と承認フロー

学生は勤務先ごとに勤務先名・都道府県・仕事内容・時給を入力する。文科省が求める「就業先名称」「具体的な就業内容」に対応する。

勤務先の確認状態：

| 状態 | 意味 | 確定 |
| --- | --- | --- |
| 確認中 | 学生が登録し、学校未確認 | 不可 |
| OK | 学校が確認済 | 可 |
| 禁止 | 風俗営業等、資格外活動の対象外 | 不可 |

新規登録は必ず「確認中」で始まる。管理者は登録から3営業日以内に確認する。未確認が3営業日を超えた勤務先は管理ボードに赤で表示する。学生には「勤務先要確認」を表示し、学校窓口へ相談するよう促す。

風俗営業・店舗型性風俗特殊営業・無店舗型性風俗特殊営業・映像送信型性風俗特殊営業・電話異性紹介営業等が営まれる場所での活動は禁止に設定する。

## 10. 18歳未満（年少者）

学生マスタの生年月日からシフト当日の満年齢を計算し、18歳未満には次を適用する。すべて確定不可。

| 条件 | 根拠 |
| --- | --- |
| 22:00〜05:00を含むシフト | 労基法61条 |
| 1日の実働が8時間超 | 労基法60条（36協定・変形労働時間制の適用なし） |
| ローリング7日の実働が40時間超 | 労基法60条 |

例外規定（交替制の16歳以上男性等）は使用しない。

## 11. 労基法上の役割分担

労基法の法定労働時間は1日8時間・1週40時間だが、36協定や変形労働時間制で適法に超える場合があり、学校はそれを把握できない。アプリは「8時間を超えた＝違法」と断定しない。

| 項目 | アプリの扱い |
| --- | --- |
| 資格外活動28時間 | 完全自動判定・確定不可 |
| 長期休業1日8時間 | 完全自動判定・確定不可 |
| 18歳未満の制限 | 完全自動判定・確定不可 |
| 深夜割増 | 計算のみ |
| 最低賃金 | 判定・確定不可 |
| 成人の1日8時間・週40時間超 | 「労基法上要確認」の注意表示のみ。確定は可 |

複数使用者間の労働時間は労基法38条1項で通算される場合があるため、注意表示は全勤務先合算で行う。

## 13. 実績確認（新設）

月末に学生が「予定どおり働いたか」を確認し、違った日だけ実績を修正する。これにより文科省・入管庁が求める「毎日の就業時間」の実績把握に対応する。

- 対象月の締切後、翌月10日までを「実績確認期間」とする（管理者が変更可）。
- 学生画面に確定済シフトを表示し、日ごとに「予定どおり」か「修正」を選ぶ。
- 修正は開始・終了・勤務先の変更、シフト削除、シフト追加。
- 実績にも予定と同じ検算を行い、28時間超・8時間超は「実績超過」として管理ボードに赤で表示する。実績は確定不可にせず記録する（違反の事実を隠さない）。
- 実績未確認の学生は管理ボードに「実績未確認」と表示する。
- 3か月ごとの学校確認は、管理ボードの「四半期確認」ボタンで対象学生の実績一覧を表示し、確認者と確認日を監査ログに残す。

実績データは MONTHLY_SUBMISSIONS の actual_json に保存し、予定（shift_json）と分けて持つ。

## 15. 状態遷移・途中保存・確定・締切

状態は未入力・下書き・確定済・締切済の4種類。途中保存は28時間を超えていても常時可能で、確定時にサーバが全条件を再検算し、1件でもブロック条件があれば確定不可とする。

前向きの遷移は学生の操作と締切時刻で進み、戻り線は「確定済の変更」と「管理者の修正許可」の2本だけ。

締切前の修正：確定済の学生が1項目でも変更すると自動で下書きに戻り、再検算後に再度「確定」が必要。以前の確定状態は維持しない。

締切：管理者が対象月ごとに設定する（例 2026年10月分＝2026/09/30 23:59）。締切後はサーバ側で更新要求を拒否し、学生には「締切済み」だけを表示する。ボタン非表示だけの制御は禁止。

管理者解除：管理者だけが学生・月・期限を指定して「修正許可」を出せる（例 251001、2026-10、2026/10/02 18:00まで）。解除は監査ログに残す。

同時実行を分散するため、締切はクラスごとに30分ずつずらして設定することを推奨する。

## 16. 3言語

対応言語は日本語・ネパール語・ベトナム語。翻訳APIは使わず、固定辞書 `I18N = { ja, ne, vi }` をアプリ内に持つ。

- 翻訳費用0円、文言が毎回変わらない、法令エラー文言を固定できる。
- 辞書キーはエラーコード・画面ラベル・ボタン名の3群に分け、追加時は3言語同時に登録する。未翻訳キーは日本語にフォールバックする。
- ネパール語（デーバナーガリー）はスマートフォンのシステムフォントで表示できる。Webフォントは読み込まない。
- 管理画面は日本語のみ。

## 18. 印刷

印刷はサーバでPDFを作らず、HTMLを生成してブラウザの印刷画面を開く方式にする。

| 種類 | 操作 | 出力 |
| --- | --- | --- |
| 個人×1か月 | 一覧の「印刷」 | 1ページ |

| 絞込み一括 | 表示中一覧の「表示中を一括印刷」 | 表示件数分 |

書式はA4横、1学生×1か月＝1ページ。予定と実績を並べて印刷し、実績超過日は網掛けにする。

```css
@page { size: A4 landscape; }
.student-page { break-after: page; }
```

## 22. 保存期間・バックアップ

各月の確定・下書き・実績データは提出対象月から最低24か月保存する。卒業時に即削除せず、学籍番号は再利用しない。

```

    /DB
        ShiftDB
        AuditLog
    /Backup

        /2027
```

月締め後に時間主導トリガーでスプレッドシートを自動コピーする。24か月を超えた行の削除は管理者が「保存期限超過データの削除」ボタンで実行し、削除件数を監査ログに残す。

## 23. 認証

学籍番号ではなく、学校が発行する非連番のログインID＋パスワードで認証する。Google Workspaceを学生分用意しない前提。

- 初期パスワードは12文字以上のランダム生成。紙で本人に手渡す。
- 初回ログイン後に変更を強制する。
- 保存はsalt＋HMAC-SHA256を10,000回反復したハッシュ。秘密鍵はScript Propertiesに置く。
- ログイン失敗5回で15分ロック。管理者はロックを即時解除できる。GASはクライアントIPを取得できないため、IP制限は行わない。ログインIDを非連番にすることで他人のIDを狙ったロックを防ぐ。
- セッションはランダム128bitトークン。ブラウザ側はJavaScript変数にのみ保持し、localStorageに書かない。有効期限120分。ページ再読み込み時は再ログインする。
- パスワード再発行は管理者が行い、監査ログに残す。
- Google Workspace for Educationが取得できる場合は、Googleログインに切り替えて独自認証を廃止する（第28章）。

## 24. 権限制御とサーバ関数の保護

Webアプリは「デプロイしたユーザーとして実行」「全員がアクセス可能」で公開する。この設定では google.script.run から呼べる公開関数はすべて外部から呼び出せるため、UIの非表示に頼らず、全サーバ関数でセッションと権限を検証する。

- 公開関数は `api_*` の1系統だけにし、内部関数は名前末尾に `_` を付けて非公開にする。
- すべての `api_*` は第1引数にセッショントークンを受け取り、`auth_()` で学生／管理者を判定してから処理する。
- 学生：自分のデータ閲覧・下書き保存・締切前修正・確定・実績確認。他学生の閲覧・変更、学校設定変更、締切変更、長期休業変更は不可。
- 管理者：全学生閲覧、締切設定、長期休業設定、勤務先確認、修正許可、四半期確認、個別・一括印刷、学生追加・卒業処理、パスワード再発行。管理者は ADMINS シートのGoogleアカウントで判定する。
- スプレッドシートは学生に共有しない。
- 通信はHTTPS。フォーム値はサーバ側で型・範囲を検証する。

## 25. 同時書き込み・Apps Script制限対策

Apps Scriptの制限は1実行6分、同時実行30／ユーザー、Properties読み書き50,000／日、トリガー合計90分／日（consumer）。「デプロイしたユーザーとして実行」のため、全学生のリクエストが所有者1名分の同時実行30に集中する。

| 対策 | 内容 |
| --- | --- |
| ロック | LockService.getScriptLock()。取得→対象行の再取得→更新→flush→解放。保持は1秒以内 |
| 読み書き | Rangeをまとめて読み書き。1セルずつの操作は禁止 |
| 実行時間 | 保存・確定は1回のリクエストで完結させ、ループは1学生分のみ |
| 同時実行 | クラス別締切で時間分散。クライアントは失敗時に2秒・4秒・8秒の指数バックオフで3回リトライし、それでも失敗なら「混雑中。1分後に再試行」を表示 |
| セッション | Script Propertiesではなく SESSIONS シートに保持し、Properties上限を消費しない |
| 印刷 | 1回のHTML生成は50名以内 |
| 禁止 | 学生ごとの別スプレッドシート、サーバ側での200個のPDF生成 |

## 26. サーバ側確定ロジック

学生が「確定」を押したらサーバ側で次を順に行う。フロント側の判定は表示用であり、合否はサーバが決める。

1. セッション認証
2. 締切確認（修正許可があれば期限内か）
3. 在籍確認
4. 資格外活動許可の有無・期限確認
5. 勤務先の確認状態・禁止判定
6. 時給と適用最低賃金の日別比較
7. 全シフトを分単位へ変換。深夜跨ぎは翌日終了、帰属日は開始日
8. 同日内の重複確認
9. 自動休憩生成
10. 実働・深夜分の計算
11. 長期休業日判定
12. 複数勤務先の合算
13. 前月確定データ・翌月データの取得
14. ローリング7日28時間検算（全日）
15. 長期休業1日8時間検算
16. 18歳未満の深夜・8時間・40時間検算
17. 成人の8時間・40時間超の注意コード付与（確定は可）
18. ブロックコード0件を確認
19. ロック取得→version＋1で確定保存→監査ログ→ロック解放

## 28. 0円構成とアカウント方針

Googleへの支払いは0円で成立する。ただし個人情報（生年月日・在留情報）を扱うため、運用アカウントは学校が管理するものに限る。

| 項目 | 使用 |
| --- | --- |
| Webアプリ | Google Apps Script（HTML Service） |
| データ | Google Sheets |
| ファイル保管・バックアップ | Google Drive（無料15GB） |
| 認証 | 独自認証（Workspace for Education取得時はGoogleログイン） |
| 3言語 | 固定辞書 |
| PDF生成・翻訳API・SMS・Firebase | 使用しない |
| 月額運営費 | 0円 |

アカウント方針：

- 個人のGmailアカウントでの運用は禁止。学校法人が管理するアカウントでデプロイし、2段階認証を必須にする。
- 学校法人はGoogle Workspace for Education Fundamentals（無償）の対象になりうる【曖昧】。取得できれば学生にアカウントを配布し、Googleログインに切り替えて独自認証を廃止する。これが最も安全な構成。
- URLは script.google.com 固定で独自ドメインは使えない。画面上部に「このアプリはGoogleが作成したものではありません」が表示される。学生への案内文に明記する。

実費はかからないが、人的コストは発生する：勤務先確認（3営業日SLA）、最低賃金マスタ点検（年2回）、パスワード発行・再発行、四半期確認。

Googleが将来無料枠・上限・仕様を変更しないことは保証できない。

## 29. 実装難所とテスト計画

難所は5つ。順に単体テストを用意してから画面を作る。

| 難所 | 対策 |
| --- | --- |
| ローリング7日＋月跨ぎ＋深夜跨ぎ＋複数勤務先の検算 | 純関数として分離し、境界ケースの単体テストを先に書く |
| 独自認証・セッション | ライブラリ化し、失敗系（期限切れ・改ざん・ロック）を必ずテスト |
| 同時実行・ロック | 30接続の負荷試験を締切前に実施 |
| 3言語辞書の保守 | 辞書キーの欠落を検出するテストを持つ |
| スマートフォンUI | iOS Safari・Android Chromeで31日入力を実機確認 |

必須テストケース：

- 10/31 22:00〜11/1 02:00 のシフトが10月に帰属し、11月のローリング7日にも含まれる
- 同日2勤務先の合算で28時間超になる
- 長期休業期間と通常期間が混在する7日間で28時間検算が維持される
- 長期休業日に8時間ちょうど＝可、8時間15分＝不可
- 拘束6時間ちょうど＝休憩0、6時間15分＝休憩45
- 18歳の誕生日をまたぐ月で、誕生日前日の深夜が不可、当日以降が可
- 最低賃金の発効日をまたぐ月で日別に判定される
- 前月が下書きのとき0分で計算され、注意コードが付く
- 締切後の保存要求がサーバで拒否される
- 修正許可の期限後に再びロックされる
- 他学生のIDを指定した閲覧・保存要求が拒否される
- ログイン5回失敗で15分ロック、管理者解除で即時復帰
