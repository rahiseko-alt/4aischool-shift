## 5. 第12章 システム導入・運用・実機確認手順書

学校のシステム管理者および運用担当者向けの手順書です。

### 手順 1: Google Apps Script プロジェクトの作成とコード配置

1. 学校が管理する Google アカウント（Google Workspace 等）で Google Drive にログインします。
2. 「新規」>「その他」>「Google Apps Script」を選択し、新しいプロジェクトを作成します。
3. プロジェクト名を「留学生アルバイト申告システム」等に変更します。
4. プロジェクトの設定（歯車アイコン）を開き、「「appsscript.json」マニフェスト ファイルをエディタで表示する」にチェックを入れます。
5. 本リポジトリの `src/` 配下にある全ファイル（`.js`, `.html`, `appsscript.json`）をエディタ上に同名で作成・コピー＆ペーストします。

### 手順 2: 初期設定（`setupInitial`）の実行

1. Apps Script エディタの関数選択プルダウンから `setupInitial` を選択し、「実行」をクリックします。
2. 初回実行時、アクセス権限の承認ダイアログが表示されるので、画面の指示に従って許可します。
3. 実行完了後、「実行ログ」画面を確認します。
4. ログに以下のような形式で初期管理者のログインIDとパスワードが出力されます：
   ```text
   INITIAL_ADMIN loginId=XXXXXX password=YYYYYYYYYYYY
   ```
   この `loginId` と `password` を安全に控えます（紛失するとログインできなくなります）。
5. Google Drive 上に自動生成された `ShiftDB` スプレッドシートと `AuditLog` スプレッドシートが存在することを確認します。

### 手順 3: バックアップ設定とトリガー登録

1. Google Drive 上に、バックアップファイルを格納するための専用フォルダを作成します（例: `アルバイト申告_月次バックアップ`）。
2. 作成したフォルダの URL からフォルダ ID（`https://drive.google.com/drive/folders/【この部分の英数字】`）をコピーします。
3. Apps Script エディタの「プロジェクトの設定」>「スクリプト プロパティ」を開きます。
4. 「スクリプト プロパティを追加」をクリックし、以下を設定して保存します：
   - プロパティ名: `BACKUP_FOLDER_ID`
   - 値: 先ほどコピーしたフォルダ ID
5. エディタの関数選択で `installTriggers` を選択し、「実行」をクリックします。
6. これにより、毎月1日午前3時台に自動バックアップ（`backupMonthly`）を実行する時間主導型トリガーが登録されます。

### 手順 4: ウェブアプリとしてのデプロイ

1. 画面右上の「デプロイ」>「新しいデプロイ」をクリックします。
2. 種類の選択で「ウェブアプリ」を選択します。
3. 設定内容を以下のように指定します：
   - 説明: `v1.0.0`
   - 次のユーザーとして実行: **自分 (アクセス元のユーザーではなくプロジェクト所有者)**
   - アクセスできるユーザー: **全員 (Anyone)**
4. 「デプロイ」をクリックし、発行された「ウェブアプリの URL」を控えます。この URL が学生および管理者の共通アクセス先となります。

### 手順 5: 管理画面でのマスタ初期登録

1. 発行されたウェブアプリ URL にブラウザでアクセスします。
2. 手順 2 で控えた初期管理者のログイン ID とパスワードでログインします。
3. 初回ログイン時はパスワード変更画面が表示されるので、新しい強固なパスワード（10文字以上）に変更します。
4. 管理画面の「マスタ設定」を開き、以下の順で登録します：
   - **学校設定**: 学校名を入力します。
   - **最低賃金**: 厚生労働省が公示している最新の地域別最低賃金を確認し、該当する都道府県・金額・発効日を登録します。
   - **長期休業設定**: 学校の学年暦に基づき、夏期休暇・冬期休暇・春期休暇などの名称・開始日・終了日・年度を登録します。
   - **締切設定**: 対象年月（例: `2026-10`）、クラス名（例: `A`）、申告締切日時（例: `2026-09-30 23:59`）、必要に応じて実績締切日時を登録します。
   - **学生の追加**: 対象学生の学籍番号、氏名、クラス、生年月日、母国語（日本語 / ネパール語 / ベトナム語）、入学日、在籍状態を登録します。登録時に初期パスワードが発行されるので学生に伝達します。

### 手順 6: 実機確認手順（iOS Safari / Android Chrome）

学生役の端末（スマートフォン）で以下の順に動作を検証します：

1. **ログインと初回強制変更**:
   - 発行された学生ログイン ID と初期パスワードでログイン。
   - パスワード変更画面が自動表示されることを確認し、新パスワードに変更。
2. **言語切替の確認**:
   - 画面上部の言語ボタン（「日本語」「नेपाली」「Tiếng Việt」）をタップし、UI ラベルが瞬時に各言語へ切り替わることを確認。
3. **勤務先の追加**:
   - 「勤務先を追加」から勤務先名・都道府県・仕事内容・時給を入力して保存。
   - 一覧に「確認中」として追加されることを確認（管理画面側で確認済みにするまで確定不可となること）。
4. **予定シフトの入力**:
   - 1日から末日までのカードまたは表が表示されていることを確認。
   - 長期休業期間の日が赤枠および「長期休暇」と明示されることを確認。
   - シフトを入力（15分刻みの時間入力 `<input type="time" step="900">`）。
5. **日跨ぎシフトの入力**:
   - `22:00` 〜 `02:00` の翌日跨ぎシフトを入力し、正常に受け付けられることを確認。
6. **途中保存**:
   - 「途中保存」ボタンをタップし、正常に保存されステータスが「下書き」となることを確認。
7. **確定**:
   - 「確定」ボタンをタップ。週28時間超過や入力エラーがある場合は適切なエラーメッセージが表示され、問題がない場合は「確定済」となることを確認。
8. **実績確認（翌月以降）**:
   - 翌月1日以降にアクセスし、「実績確認」ブロックが表示されること、「予定どおり」または「修正」を行って確定できることを確認。

### 手順 7: 締切前の負荷確認手順（同時アクセステスト）

月末の締切直前におけるアクセス集中（約30名の同時保存）を想定した確認手順です：

1. **準備**:
   - テスト用学生アカウントを 30 名分用意し、それぞれログインして入力可能な状態にします。
2. **同時実行**:
   - 複数端末または複数ブラウザタブから、同一の締切時刻直前（または同時刻）に一斉に「途中保存」または「確定」を実行します。
3. **確認ポイント**:
   - GAS の `LockService` による排他制御が働き、リクエストが順次処理されること。
   - ロック取得待ちが重なった場合でも、自動再試行（2秒・4秒・8秒）が行われること。
   - 最終的に「混雑中。1分後に再試行」（エラーコード: `BUSY`）以外の致命的なシステムエラー（500エラーや画面のクラッシュ）が発生しないこと。
   - 処理が成功したデータが `ShiftDB` スプレッドシートに欠損なく正確に書き込まれ、監査ログ（`AuditLog`）に履歴が記録されていること。
