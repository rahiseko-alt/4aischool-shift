## Problem Statement

専修学校には在留資格「留学」の学生が約200名在籍し、毎年約100名が入れ替わる。学校は文部科学省から、3か月に1度、資格外活動許可の有無・就業先名称・具体的な就業内容・**毎日の就業時間**を正確に把握するよう求められている。

いまは、学生が申告した予定が「どの7日間をとっても28時間以内か」「長期休業中は1日8時間以内か」「18歳未満の深夜勤務は無いか」「時給が最低賃金を下回っていないか」を、人の目で確かめるしかない。深夜をまたぐ勤務、同じ日の掛け持ち、月の変わり目にまたがる7日間があるため、手計算では見落としが起きる。見落とせば学生の在留資格に関わり、学校の在籍管理の責任も問われる。

学生の側も、日本語・ネパール語・ベトナム語の話者で、法令の細かい規則を自分で当てはめるのは難しい。予定だけでは「実際に働いた時間」の記録が残らず、国への報告要件も満たせない。

## Solution

学生はスマートフォンで翌月の予定シフトを1ページに入力して確定し、月末には実績シフトを確認する。休憩・実働・深夜・給与の概算・法令の検算はすべて自動で行う。確定の前にサーバが全条件を検算し、違反が1件でもあれば確定させない。途中保存はいつでもできる。

実績は違反があっても隠さずに記録し、管理者に知らせる。学校は管理ボードで、全学生の申告状態・エラー・勤務先の確認待ち・実績の未確認を把握する。勤務先の確認、締切後の修正許可、在籍していない学生の学校確定、四半期確認、印刷ができる。

Google Apps Script・Google Sheets・Google Drive だけで動かし、Google への支払いは0円とする。

## User Stories

### 学生: ログインと言語

1. 学生として、学校から紙で受け取ったログインIDと初期パスワードでログインしたい。学籍番号を知られても他人に成りすまされないためだ。
2. 学生として、初回ログインの直後にパスワードの変更を求められたい。紙の初期パスワードが漏れても安全にするためだ。
3. 学生として、パスワードを5回間違えたら15分ロックされ、そのことを知らされたい。自分のアカウントが総当たりで破られないためだ。
4. 学生として、画面を日本語・ネパール語・ベトナム語から選びたい。母語で間違いなく入力するためだ。
5. 学生として、エラーは「28時間超過」のような短い固定語で表示してほしい。長い説明文に惑わされず、何が悪いかすぐ分かるためだ。
6. 学生として、ページを再読み込みしたら再ログインを求められたい。共用の端末でもログイン状態が残らないためだ。
7. 学生として、120分操作しないと自動でログアウトしてほしい。端末を置き忘れても他人に使われないためだ。

### 学生: 勤務先

8. 学生として、勤務先名・都道府県・仕事内容・基本時給を登録したい。学校が就業先を把握できるようにするためだ。
9. 学生として、任意で早朝手当（時間帯と1時間あたりの金額）を登録したい。給与の概算を実態に近づけるためだ。
10. 学生として、登録した勤務先が「確認中」「OK」「禁止」のどれかを見たい。確定できない理由が分かるためだ。
11. 学生として、確認中の勤務先には「勤務先要確認」と表示され、窓口に相談するよう促されたい。締切前に手続きを進めるためだ。
12. 学生として、複数の勤務先を登録したい。掛け持ちを正しく申告するためだ。

### 学生: 予定シフトの入力

13. 学生として、対象月の31日分を日ごとのカードで縦に並べて見たい。スマートフォンで迷わず入力するためだ。
14. 学生として、1日に複数のシフトを、それぞれ勤務先を選んで入力したい。同じ日の掛け持ちを申告するためだ。
15. 学生として、開始・終了を15分単位で入力したい。入力の揺れをなくすためだ。
16. 学生として、22:00〜02:00 のように日付をまたぐ勤務を、そのまま入力したい。深夜勤務を正しく申告するためだ。
17. 学生として、休憩を入力しなくても自動で決まってほしい。休憩の規則を覚えなくて済むためだ。
18. 学生として、シフトごとに休憩・実働・深夜・予定給与が自動表示されてほしい。働く量と収入の見通しを立てるためだ。
19. 学生として、長期休業日の行が赤枠で「長期休暇」と表示されてほしい。1日8時間の上限がかかる日だと分かるためだ。
20. 学生として、同じ日のシフトが重なったら保存できないようにしてほしい。入力ミスに気づくためだ。
21. 学生として、16時間を超える勤務は入力エラーにしてほしい。打ち間違いに気づくためだ。
22. 学生として、28時間を超えていても途中保存はしたい。入力の途中で作業を失わないためだ。
23. 学生として、確定ボタンを押したら、全条件が検算され、違反があれば理由の固定語が出て確定されないでほしい。違反した予定を出してしまわないためだ。
24. 学生として、違反が無ければ「確定済み」とだけ表示されたい。「法律上問題ありません」と誤解させる表示を見ないためだ。
25. 学生として、成人で1日8時間・7日40時間を超える予定には「労基法上要確認」の注意だけが出て、確定はできてほしい。雇用先の協定で認められている場合に困らないためだ。
26. 学生として、前月が未確定なら「前月未確定」の注意を見たい。月の変わり目の検算が不完全だと分かるためだ。
27. 学生として、確定済みの予定を締切前に1か所でも変えたら、自動で下書きに戻ってほしい。変えた内容が検算されずに通らないためだ。
28. 学生として、その月に働かないなら、シフト0件のまま自分で確定したい。「勤務なし」を本人の申告として残すためだ。
29. 学生として、締切後は「締切済み」とだけ表示され、変更できないでほしい。締切の意味がはっきりするためだ。
30. 学生として、学校から修正許可が出たら、その期限までは締切後でも直して確定したい。事情があるときに救済されるためだ。
31. 学生として、通信が混んで失敗したら自動で数回やり直し、それでも駄目なら「混雑中。1分後に再試行」と表示されたい。締切直前に何が起きたか分かるためだ。
32. 学生として、別の端末で先に保存していた場合は、上書きせずにそのことを知らされたい。古い内容で新しい内容を消さないためだ。
33. 学生として、提出期限と対象月を画面の上部で見たい。締切を忘れないためだ。
34. 学生として、過去の月の提出状態の一覧を見たい。自分の申告の履歴を確かめるためだ。

### 学生: 実績確認

35. 学生として、対象月が終わったら、確定済みの予定を実績として表示してほしい。違った日だけ直せば済むためだ。
36. 学生として、日ごとに「予定どおり」か「修正」を選びたい。確認の手間を減らすためだ。
37. 学生として、実績で開始・終了・勤務先の変更、シフトの削除・追加をしたい。実際の就業時間を正確に残すためだ。
38. 学生として、予定を出していなかった月も実績は入力したい。実際に働いた事実を記録するためだ。
39. 学生として、実績の入力ミス（重なり・16時間超・入力不足）は保存できないでほしい。記録が壊れないためだ。
40. 学生として、実績が28時間などを超えていても保存はできてほしい。事実を隠さずに学校へ伝えるためだ。
41. 学生として、実績確認の期限を過ぎたら変更できないでほしい。記録が後から書き換わらないためだ。

### 管理者: ログインと権限

42. 管理者として、学生と別のログインIDとパスワードでログインしたい。学校のアカウントが Google Workspace でなくても管理画面に入れるためだ。
43. 管理者として、管理画面は日本語だけで見たい。事務作業に集中するためだ。
44. 管理者として、学生には管理者の操作が一切できないようにしたい。画面を隠すだけでなく、サーバ側で拒否してほしい。
45. 管理者として、学生が他の学生のデータを見たり保存したりできないようにしたい。個人情報を守るためだ。

### 管理者: 管理ボード

46. 管理者として、対象月とクラスで絞り込み、学生数・確定済・下書き・未提出・エラーの件数を見たい。全体の進み具合を把握するためだ。
47. 管理者として、勤務先の確認待ち件数と、そのうち3営業日を超えた件数を見たい。確認の期限を守るためだ。
48. 管理者として、実績未確認の件数を見たい。学生に催促するためだ。
49. 管理者として、学生一覧で学籍番号・氏名・クラス・状態・エラー・実績・更新日を見たい。個別に対応すべき学生を探すためだ。
50. 管理者として、学籍番号・氏名で検索し、状態で絞り込みたい。目的の学生にすぐ辿り着くためだ。
51. 管理者として、実績が法令の上限を超えた学生を赤で見たい。指導が必要な学生を見逃さないためだ。
52. 管理者として、学校確定で「対象外」になった月は、一覧と印刷で「対象外」と表示してほしい。勤務0時間と区別するためだ。

### 管理者: 確認・許可・学校確定

53. 管理者として、学生が登録した勤務先を「OK」か「禁止」にしたい。風俗営業等の就業を止めるためだ。
54. 管理者として、確認者と確認日を記録したい。誰が判断したかを後で説明するためだ。
55. 管理者として、学生・月・期限を指定して修正許可を出したい。締切後の救済を管理者だけができるようにするためだ。
56. 管理者として、修正許可の期限が過ぎたら自動で再び締まってほしい。解除のし忘れを防ぐためだ。
57. 管理者として、退学・休学・卒業の学生の未入力の月を「学校確定」にしたい。管理ボードに「未提出」のまま残らないためだ。
58. 管理者として、在籍中の学生には学校確定ができないようにしたい。本人の申告を学校が勝手に埋めないためだ。
59. 管理者として、四半期確認ボタンで対象学生の3か月分の実績一覧を見て、確認を記録したい。文部科学省の求める3か月ごとの把握を証明するためだ。

### 管理者: マスタと設定

60. 管理者として、学生を追加し、生年月日・クラス・入学日・在籍状態・資格外活動許可と期限を登録したい。判定の元になる情報を持つためだ。
61. 管理者として、退学日・卒業日を登録したい。その日より後のシフトを「在籍対象外」にするためだ。
62. 管理者として、新しい学生に連番でないログインIDと、12文字以上のランダムな初期パスワードを発行したい。紙で本人に渡すためだ。
63. 管理者として、パスワードを再発行し、ログインロックを即時に解除したい。学生が締切前に締め出されないためだ。
64. 管理者として、長期休業期間（名称・開始・終了・年度）を登録したい。1日8時間の判定を学則に合わせるためだ。
65. 管理者として、対象月・クラスごとに予定の締切と実績確認の期限を設定したい。締切をクラスごとにずらして混雑を避けるためだ。
66. 管理者として、都道府県別の最低賃金を発効日・終了日つきで登録したい。発効日をまたぐ月も日ごとに正しく判定するためだ。
67. 管理者として、休学中の学生が確定できるかを設定で切り替えたい。学則の判断に合わせるためだ。
68. 管理者として、学校名・保存期間・セッションの有効期限・勤務先確認の期限日数を設定したい。運用に合わせるためだ。

### 管理者: 印刷・保存・監査

69. 管理者として、学生1人1か月を A4 横1ページで印刷したい。個別の面談や保管に使うためだ。
70. 管理者として、学生1人の2年間分をまとめて印刷したい。在籍期間の記録を一度に出すためだ。
71. 管理者として、クラス単位、または表示中の一覧を、1回50名までに分けて一括印刷したい。ブラウザを固まらせずに全員分を出すためだ。
72. 管理者として、印刷に予定と実績を並べ、実績の超過日を網掛けにしてほしい。違反の日が一目で分かるためだ。
73. 管理者として、学生の操作と管理者の操作がすべて、別の追記専用の記録に残ってほしい。後から経緯を説明し、改ざんを見つけるためだ。
74. 管理者として、月の締め後にデータと記録が自動でバックアップされてほしい。事故のときに戻せるためだ。
75. 管理者として、24か月を超えたデータをボタンで削除し、削除件数を記録したい。保存期間を守りつつ、個人情報を持ちすぎないためだ。

## Implementation Decisions

### 全体構成

- Google Apps Script の Web アプリ（HTML Service）として作る。「デプロイしたユーザーとして実行」「全員がアクセス可能」で公開する。
- データは1つのスプレッドシート（ShiftDB）、監査ログは別のスプレッドシート（AuditLog）に置く。
- PDF 生成・翻訳 API・外部ライブラリ・Web フォントは使わない。
- サーバ側のコードは、GAS と Node.js の両方でそのまま読み込める普通の JavaScript で書く。モジュール構文（import/export）は使わない。
- 日付は内部ではすべて Asia/Tokyo の `YYYY-MM-DD` 文字列、時刻は `HH:MM` 文字列で扱う。時間の計算はすべて整数の分で行う。Date オブジェクトの時差に依存する計算は、計算の心臓部に持ち込まない。

### モジュール1: 計算の心臓部（純粋関数）

画面・スプレッドシート・現在時刻・乱数に一切触れない。同じ入力には必ず同じ出力を返す。予定と実績の両方で、同じ関数を使う。

入口は1つ。

```
evaluateMonth(input) -> result

input = {
  yearMonth: "2026-10",
  mode: "plan" | "actual",
  student: { birthDate, enrollmentDate, withdrawalDate|null, graduationDate|null,
             status: "在籍"|"休学"|"卒業"|"退学",
             workPermission: boolean, permissionExpires: "YYYY-MM-DD"|null },
  workplaces: [{ id, prefecture, baseHourlyWage,
                 earlyStart|null, earlyEnd|null, earlyPremium|null,
                 verificationStatus: "確認中"|"OK"|"禁止" }],
  shifts: { "1": [{ workplace, start: "HH:MM", end: "HH:MM" }], ... },
  prevMonthDaily: { "YYYY-MM-DD": 実働分 },   // 前月の最終6日分。取得元の決定は下記
  prevMonthSource: "actual"|"confirmed"|"none"|"not_applicable",
  nextMonthDaily: { "YYYY-MM-DD": 実働分 },   // 翌月の最初の6日分。無ければ空
  holidays: [{ startDate, endDate }],
  minimumWages: [{ prefecture, amount, effectiveFrom, effectiveTo|null }],
  settings: { allowLeaveOfAbsence: boolean }
}

result = {
  shifts: { "1": [{ workplace, start, end, breakMinutes, breakStart, breakEnd,
                    boundMinutes, workMinutes, nightMinutes, earlyMinutes, salaryYen }] },
  daily: { "YYYY-MM-DD": 実働分 },           // 対象月の各日
  totalMinutes, maxRolling7Minutes, estimatedSalaryYen,
  codes: [{ code, severity: "block"|"warn"|"admin", date?, shiftIndex? }],
  inputErrors: [{ code, date, shiftIndex }]  // 保存そのものを止めるもの
}
```

判定規則（すべて `decisions-2026-09-29.md` と原文に基づく）:

- **時刻**: 00・15・30・45 分以外は入力エラー `INVALID_TIME`。開始・終了・勤務先の欠落は `MISSING`。
- **日付またぎ**: 終了 ≦ 開始なら翌日終了。**帰属日**は開始日。
- **拘束時間**が960分（16時間）を超えたら入力エラー `SHIFT_TOO_LONG`。
- **重なり**: 実時間で重なるシフトは、日付をまたぐものを含めて入力エラー `SHIFT_OVERLAP`。
- **休憩**: 拘束が360分以下なら0、360分を超え480分以下なら45、480分を超えれば60。休憩開始 ＝ 開始 ＋ floor(((拘束 − 休憩) ÷ 2) ÷ 15) × 15。
- **実働** ＝ 拘束 − 休憩。
- **深夜分**: 実働のうち、開始日の 00:00〜05:00 と 22:00〜翌05:00 に含まれる分。休憩と重なる分は除く。
- **早朝分**: 勤務先に早朝手当があるとき、実働のうち各暦日の早朝時間帯に含まれる分。休憩と重なる分は除く。
- **給与**: シフトごとに floor(時給 × 実働 ÷ 60) ＋ floor(時給 × 深夜 ÷ 240) ＋ floor(早朝手当 × 早朝分 ÷ 60)。整数演算で行い、小数を経由しない。
- **長期休業日**: いずれかの長期休業期間の開始日〜終了日（両端含む）に入る日。土日・祝日も含む。
- **28時間（ローリング7日）**: 対象月の日を1日でも含む、すべての連続7日間について、全勤務先の実働を合計する。7日すべてが長期休業日の窓は検算しない。1,680分を超えたら `OVER_28H`。
- **長期休業1日8時間**: 長期休業日の実働が480分を超えたら `OVER_8H_HOLIDAY`。
- **在籍**: シフトの帰属日が入学日より前、退学日・卒業日より後なら `NOT_ENROLLED`。在籍状態が休学で、設定が「休学は確定不可」なら、すべてのシフトが `NOT_ENROLLED`。
- **資格外活動許可**: シフトが1件以上あり、許可が無ければ `NO_PERMIT`。帰属日が許可期限より後なら `PERMIT_EXPIRED`。
- **勤務先**: シフトで使われている勤務先が確認中なら `WORKPLACE_PENDING`、禁止なら `WORKPLACE_BANNED`。使われていない勤務先は判定しない。
- **最低賃金**: 帰属日に有効な、その都道府県の金額と時給を比べる。下回れば `WAGE_LOW`。該当する金額が登録されていなければ `MINWAGE_MISSING`（block）。
- **満年齢**: 帰属日に誕生日を迎えていれば加齢する。2月29日生まれは、平年は3月1日に加齢する。
- **18歳未満**: 実働が深夜帯と1分以上重なれば `MINOR_NIGHT`。帰属日の実働合計が480分を超えれば、または年少者の日を含む7日間の実働合計が2,400分を超えれば `MINOR_OVER`。
- **成人の注意**: 帰属日の実働合計が480分超、または7日間の合計が2,400分超なら `LABOR_HOURS`（warn）。
- **前月**: `prevMonthSource` が `none` なら `PREV_MONTH_DRAFT`（warn）。`not_applicable`（前月は入学前・対象外）なら付けない。前月が勤務なし（シフト0件で確定）なら `confirmed` で、0分として数える。
- **mode = "actual"**: 入力エラーは同じく保存を止める。それ以外の block コードはすべて severity を `admin` に置き換え、`OVER_28H`・`OVER_8H_HOLIDAY`・`MINOR_*` のいずれかがあれば `ACTUAL_OVER`（admin）も付ける。

エラーコード一覧（原文第14章に以下を追加）: `INVALID_TIME`（時刻不正）、`SHIFT_OVERLAP`（時間重複）、`SHIFT_TOO_LONG`（16時間超）、`MINWAGE_MISSING`（最低賃金未登録）。

### モジュール2: サーバの窓口（`api_*` 関数）

- ブラウザから呼べるのは `api_` で始まる関数だけ。それ以外のサーバ関数は名前の末尾に `_` を付ける。
- すべての `api_*` は、第1引数にセッショントークンを受け取る（ログインを除く）。最初に認証と権限の確認を行い、返り値は必ず `{ ok: true, data }` か `{ ok: false, error: コード, details? }` の形にする。
- 窓口のエラーコード: `AUTH_REQUIRED`、`FORBIDDEN`、`PASSWORD_CHANGE_REQUIRED`、`LOGIN_LOCKED`、`LOGIN_FAILED`、`DEADLINE_PASSED`、`NOT_OPEN`（締切が未設定、または実績の受付前）、`VERSION_CONFLICT`、`VALIDATION_FAILED`（details に計算の心臓部のコード）、`BUSY`、`NOT_FOUND`、`BAD_REQUEST`、`INTERNAL`（想定外の例外）。
- 学生用の窓口: ログイン、ログアウト、パスワード変更、自分の月次申告の取得、勤務先の登録・更新、下書き保存、確定、実績の取得・保存・確定、自分の提出履歴。
- 管理者用の窓口: 管理ボード、学生詳細、学生の追加・更新（退学日・卒業日を含む）、ログインID・初期パスワードの発行、パスワード再発行、ログインロック解除、勤務先の確認、修正許可、学校確定、四半期確認、締切の設定、長期休業の設定、最低賃金の設定、学校設定、印刷用 HTML の生成、保存期限超過データの削除。
- 学生の窓口は、引数で学籍番号を受け取らない。対象の学生は必ずセッションから決める。
- 保存・確定は、読んだ時の `version` を一緒に送る。保存時点の version と違えば `VERSION_CONFLICT` を返し、上書きしない。成功するたびに version を1増やす。
- 保存の処理順: 検算（ロックの外）→ スクリプトロック取得（待ちは最大5秒。取れなければ `BUSY`）→ 対象行の再読込 → version 照合 → まとめて書き込み → 解放 → 監査ログ追記。

### 月次申告の状態

- 保存する状態は `未入力`・`下書き`・`確定済`・`学校確定` の4つ。
- `締切済` は保存せず、その都度判定する。現在時刻が学生のクラスの締切を過ぎ、有効な修正許可が無いとき、締切済として扱う。管理ボードの表示状態は締切の前後で変えない（確定済→確定済、下書き→下書き、未入力→未提出）。
- 確定済みの月を下書き保存すると、状態は下書きに戻る。
- 学校確定は、在籍状態が退学・休学・卒業で、その月が未入力の学生にだけ行え、結果は「対象外」になる。それ以外は `FORBIDDEN`。
- 勤務なし: 在籍中の学生がシフト0件で確定したもの。状態は確定済で、合計0分。

### 前月データの取得元（窓口側で決めて、計算の心臓部に渡す）

- 前月の実績が確認済み（予定どおり／修正あり）なら、実績を使う（`actual`）。
- そうでなく、前月が確定済みなら予定を使う（`confirmed`）。
- 前月が入学前・学校確定（対象外）なら `not_applicable`。それ以外は0分で `none`。

### 実績確認

- 実績確認の期間は、対象月の翌月1日 00:00 から、実績確認期限（既定は翌月10日 23:59。締切の表で月・クラスごとに変更可）まで。
- 予定を確定していない月でも、実績は入力できる。
- 実績の状態は `未確認`・`予定どおり`・`修正あり`。予定と実績が完全に同じなら「予定どおり」とする。

### 認証とセッション

- ログインIDは、紛らわしい文字（0・O・1・I・l）を除いた英数字8文字のランダム。学籍番号とは別に発行し、再利用しない。
- 初期パスワードは12文字以上のランダム。学生が自分で決めるパスワードは10文字以上。
- パスワードの保存: ユーザーごとのランダムな salt と、Script Properties に置く秘密鍵を使い、HMAC-SHA256 を反復する。反復回数はユーザーごとに保存する（既定10,000）。比較は時間が一定になる方法で行う。
- 5回連続で失敗したら15分ロック。成功で失敗回数を0に戻す。管理者はロックを即時に解除できる。
- 管理者も同じ仕組みでログインする。USERS に role（`student`／`admin`）を持つ。原文の ADMINS シートは使わない。
- セッションは128ビットのランダムなトークン。SESSIONS シートには、トークンそのものではなくそのハッシュを保存する。有効期限はログインから120分（設定で変更可）。
- 初回ログインや再発行の後は、パスワード変更以外のすべての窓口が `PASSWORD_CHANGE_REQUIRED` を返す。
- ブラウザ側は、トークンを JavaScript の変数だけに持ち、localStorage・sessionStorage・Cookie に書かない。

### データ（原文第19・20章からの変更点のみ）

- STUDENTS に `withdrawal_date`（退学日）を追加。
- USERS に `role` を追加。
- MONTHLY_SUBMISSIONS の `status` は `未入力`／`下書き`／`確定済`／`学校確定`。
- shift_json・actual_json に保存するのは、学生が入力した値（勤務先・開始・終了）だけ。休憩・実働・深夜・給与は保存時に計算の心臓部で出し、集計列（合計分・7日最大・給与合計・コード一覧）に保存する。
- SESSIONS シートを追加（トークンのハッシュ、ログインID、役割、有効期限）。
- ADMINS シートは作らない。
- SETTINGS に `allow_leave_of_absence`（既定 false）と `actual_confirm_default_day`（既定10）を追加。

### 保存先の差し替え口

- スプレッドシート・スクリプトロック・Script Properties・現在時刻・乱数・HMAC への触れ方は、すべて1つの「保存先」部品の中に閉じ込める。窓口の関数はこの部品だけを使う。
- テストでは、この部品を Node.js 上で動く偽物（メモリ上の表・偽のロック・自由に進められる時計）に差し替える。

### 画面

- 学生画面はスマートフォン優先で、31日分を日ごとのカードで縦に並べる。PC 幅では表形式にする。
- 時刻入力は `<input type="time" step="900">`。
- 画面上の検算は表示用。確定の合否は必ずサーバが決める。
- 通信に失敗したら、2秒・4秒・8秒待って最大3回やり直す。それでも駄目なら「混雑中。1分後に再試行」と表示する。
- 画面見本は、色・配置・雰囲気の参考だけにする。見本に載っている文字・数字・項目・曜日は使わない（見本には曜日のずれ、学籍番号でのログイン、PDF ボタン、1日1行、200名一括印刷などの誤りがある）。

### 3言語

- 固定の辞書を ja・ne・vi の3つで持つ。キーは「エラーコード」「画面ラベル」「ボタン名」の3群に分ける。
- 実行時、訳が無いキーは日本語で表示する。ただしテストでは、訳の欠けたキーを失敗として検出する。
- 管理画面は日本語だけ。

### 印刷

- サーバで PDF は作らない。印刷用 HTML を生成し、ブラウザの印刷画面を開く。
- A4 横、1学生×1か月＝1ページ。予定と実績を並べ、実績の超過日は網掛け、対象外の月は「対象外」と表示する。
- 1回に生成する HTML は50名まで。51名以上を求められたら `BAD_REQUEST`。

### 監査ログ・バックアップ・保存期間

- 監査ログは AuditLog スプレッドシートに追記だけを行う。記録する操作: SAVE_DRAFT、CONFIRM、ACTUAL_SAVE、ACTUAL_CONFIRM、LOGIN_OK、LOGIN_FAIL、PASSWORD_CHANGE、PASSWORD_RESET、LOGIN_UNLOCK、ADMIN_UNLOCK、SCHOOL_CONFIRM、WORKPLACE_VERIFY、QUARTER_CHECK、MASTER_UPDATE、PURGE。
- 月の締め後、時間主導のトリガーで両方のスプレッドシートを Drive のバックアップフォルダに複製する。
- 保存期限（既定24か月）を超えた行の削除は、管理者のボタン操作でだけ行い、件数を監査ログに残す。

### 営業日

- 勤務先確認の「3営業日」は、月〜金のうち、登録された長期休業期間を除いた日で数える。国民の祝日は数えない（祝日の暦を持たないため）。

## Testing Decisions

### 良いテストとは

- 外から見える振る舞いだけを確かめる。関数の中の途中経過や、内部の関数名には依存しない。
- 1つのテストは、1つの規則の境界を1つ確かめる（例: 長期休業日の8時間ちょうどは可、8時間15分は不可）。
- 期待値は、仕様から手計算した具体的な数値で書く。実装のコードから期待値を作らない。
- テストの正解表とテストコードは Claude が先に書く。実装役はテストの追加はしてよいが、既存のテストの変更・削除・スキップはしてはならない。

### テストする場所（2か所）

1. **計算の心臓部** `evaluateMonth`: 入力と出力の組だけで確かめる。法令判定の全規則と、原文第29章の必須テストをすべて含める。代表的な境界:
   - 10/31 22:00〜11/1 02:00 が10月に帰属し、11月の7日間の計算にも前月分として入る
   - 同じ日の2勤務先の合算で28時間を超える
   - 長期休業と通常期間が混ざった7日間では28時間の検算が続き、7日すべてが長期休業日になると止まる
   - 長期休業日の8時間ちょうどは可、8時間15分は不可
   - 拘束6時間ちょうどは休憩0、6時間15分は休憩45、8時間ちょうどは45、8時間15分は60
   - 09:00〜18:00 の休憩は 13:00〜14:00、22:00〜06:15 の休憩は 01:30〜02:30
   - 18歳の誕生日の前日の深夜は不可、当日以降は可。2月29日生まれ
   - 最低賃金の発効日をまたぐ月で、日ごとに判定される
   - 22:00 終了・05:00 開始は深夜にかからない
   - 前月の取得元が none のとき0分で計算され、注意が付く
   - 給与の端数（例: 時給1,015円）の切り捨て
   - 月末日（30日・31日・2月の28日と29日）の扱い
   - 実績モードでは法令超過が保存を止めず、ACTUAL_OVER が付く
2. **サーバの窓口** `api_*`: 偽の保存先に差し替え、ブラウザと同じ入口から呼ぶ。代表的なケース:
   - 締切後の保存が拒否される。修正許可の期限内は通り、期限を過ぎると再び拒否される
   - 学生の窓口は、他の学生のデータを読めず、書けない
   - 学生のトークンで管理者の窓口を呼ぶと FORBIDDEN
   - トークンなし・期限切れ・改ざんされたトークンは AUTH_REQUIRED
   - 5回の失敗で15分ロック、管理者の解除ですぐ戻る、16分後にも戻る
   - 初回ログイン後、パスワード変更以外の窓口が PASSWORD_CHANGE_REQUIRED
   - 古い version での保存が VERSION_CONFLICT になり、データが変わらない
   - 確定済みを下書き保存すると下書きに戻る
   - ロックが取れないと BUSY
   - 学校確定は在籍中の学生に使えない
   - 51名以上の印刷要求は BAD_REQUEST
   - 各操作で監査ログに1行追記される

### そのほか

- 3言語の辞書: すべてのキーが ja・ne・vi にそろい、空文字が無いことを確かめる。計算の心臓部と窓口のエラーコードが、すべて辞書に載っていることも確かめる。
- 画面: 自動テストはしない。iOS Safari と Android Chrome の実機で、31日分の入力・日付またぎ・3言語表示を確かめる手順書を付ける。
- 同時実行30接続の負荷試験は、締切前に学校の本番環境で行う（手順書を付ける）。

### 実行環境と先例

- テストは Node.js（22以上）の標準のテスト機能で動かす。外部のテスト用ライブラリは入れない。
- サーバのコードは、テストの中で GAS と同じく「全部を1つの場所に読み込む」方式で読み込む。
- このリポジトリにはまだコードもテストも無いため、先例は無い。
