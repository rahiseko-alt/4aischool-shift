## サーバ側で直したこと

| 問題 | 影響 | 直し方 |
| --- | --- | --- |
| 本物のスプレッドシートが `"2026-10"` などを日付・時刻・数値に自動変換する | 年月で行が見つからない、セッションが切れない、ロックが解けないなど、本番で全面的に壊れる（偽物のシートでは起きないためテストは通っていた） | ShiftDB へは値の先頭に `'` を付けて書き、読むときに外す。シートは作成時に書式なしテキストにする |
| 勤務先名などに `=USERS!E2` のような数式を入れられる | 他の学生のデータやパスワードのハッシュが読み出せる | 上と同じ対策。監査ログは数式として解釈される文字で始まる値だけを無害化 |
| 学校設定に範囲外の値（保存期間 -5 など）を入れられる | 保存期限超過の削除で、今のデータまで消える | 項目と範囲を固定し、外れたら BAD_REQUEST |
| セッションの有効期限が設定を無視して120分固定 | 設定が効かない | 設定の分数を使う |
| 期限切れセッションが消えない | SESSIONS が増え続け、毎回の読み込みが遅くなる | ログインのたびに期限切れを消す |
| ログアウトがロックの外で行番号削除 | 同時に動くと他人のセッションを消しうる | ロックの中で読み直してから消す |
| 学籍番号が空だと管理者の行に当たる | 空の学籍番号で初期管理者のパスワードを再発行できる | 学生の行（role が student）だけを探す |
| ロックが切れた直後の1回の失敗で再ロック | 学生が締め出される | ロックが切れたら失敗回数を0に戻す |
| ログインID・パスワードの作り方が偏っていた | 推測されやすい | 乱数から偏りなく選ぶ方式に変更。ログインIDの重複も確認 |
| 管理者の入力（修正許可・締切・最低賃金・長期休業・学生情報）の検証が甘い | 壊れた値が保存される | 日付・日時・年月・金額・必須項目を検証 |
| 勤務先の登録・変更が監査ログに残らない | 仕様違反 | MASTER_UPDATE を記録 |
| `setupInitial` の途中で失敗すると再実行できない | 初期設定のやり直しができない | 完了の印を最後に置く |
| `installTriggers` を画面から呼ばれると作り直される | 誰でもトリガーを消せる | すでにあれば何もしない |
| 未登録の学籍番号を印刷すると「許可あり」の架空の頁が出る | 誤った記録 | 「未登録」と表示し、許可なしとして扱う |

追加したもの（窓口の返り値に項目を足しただけで、既存の項目は変えていない）:

- `api_getMonth` の `student: { studentId, name }`（画面の上部に氏名を出すため）
- `api_adminBoard` の各行の `pendingWorkplaces`（確認待ちの勤務先がある学生を一覧で探すため）

## 画面側で直したこと

- 勤務先と月のデータを並行して取り、先に届いた方で描いていたため、勤務先の選択肢が空の状態で保存するとシフトがすべて消えることがあった。両方そろってから描くように変更
- 入力途中の行を黙って捨てていた。サーバへ送って「入力不足」で止めるように変更
- 勤務先の確認状態の文字の照合が誤っており、確認済みでも「要確認」と表示していた
- 学生の追加が7回の入力欄の連続で、学籍番号を空で送っていたため必ず失敗していた。資格外活動許可も常に「あり」になっていた。入力フォームに作り直した
- 管理画面に無かった機能を追加: 四半期確認、勤務先の OK／禁止、学生情報の編集、長期休業の削除、最低賃金の一覧、学校設定の全項目
- 休憩・実働・深夜・予定給与と、エラーの固定語を画面に表示
- 実績の「予定どおり」が1件目しか写していなかった。その日の予定をすべて写すように変更
- ログイン欄の「学籍番号 または ログインID」（画面見本の誤りの写し）を「ログインID」に変更
- 長期休業日に余計な説明文を出していたのを削除（「長期休暇」だけにする）
- エラーをコードのまま出していた管理画面を、辞書の固定語で表示するように変更
- 印刷の窓をあとから開いていたためポップアップが止められていた。先に窓を開けるように変更。クラス一括では対象外の学生も印刷
- スマートフォン幅で管理者のログアウトボタンが消えていた
- パスワード欄の「8文字以上」を「10文字以上」に修正
