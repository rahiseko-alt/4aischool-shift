# 点検記録 2026-11-06

対象: 本番のアプリ（版 @50）、本番のデータ（読むだけ）、src/ のコード。点検は3つに分けて同時に行った（サーバーの処理／画面と印刷／本番データ）。
本番には何も書き込んでいない。個人情報（氏名・生年月日・署名など）はこの記録に書かない。

## 致命的

### 1. いずれ誰もログインできなくなる（セッションの表の行が減り続ける）
- 場所: src/Db.js `db_deleteRowsWhere_`・`db_deleteRow_`、src/Auth.js のセッションの片付けとログアウト
- 仕組み: ログインで行を足し（空き行を使う）、ログアウトや期限切れの片付けでは行そのものを消す。空き行は減る一方で戻らない。空き行が尽きた後に全員のセッションが切れると、片付けが「見出し以外の行をすべて消す」操作になる。本物のシートはこの操作を拒むので、ログインが INTERNAL で失敗し、管理者も学生も入れなくなる。また `db_insertRows_` は空き行が尽きると範囲外への書き込みになる【曖昧】
- 本番の証拠: SESSIONS の行数は 853（作成時は 1000）。すでに 147 行減っている
- 再現: 偽のシートに本物の行数の動きを足し、ログインとログアウトを1000回繰り返したあと時計を5時間進めると、学生・管理者とも INTERNAL になった
- 残り: あと約850回のログアウトや片付けで尽きる見込み【曖昧: 使われ方による】
- 状態: 未修正

## 重大

### 2. 全角で入れると学籍番号でも短い番号でもログインできない
- 場所: src/Auth.js `auth_findStudentForLogin_`（前後の空白を除き、大文字にするだけ）、src/client_js.html のログイン
- 例: 「ＡＩＢＣ２６００１」「Ｋ０２」「K０２」、見えない文字が付いた番号は失敗する。学生の登録の側は全角を半角にそろえていて、食い違っている
- 状態: 未修正。ログインできないと言っている学生の原因の候補

### 3. 署名の画像で、表の読み込みが重くなっていく【曖昧: 計算による推定】
- 場所: src/Student.js ほか。MONTHLY_SUBMISSIONS の行に署名（最大4.5万字）が入り、操作のたびに表全体を読む
- 見込み: 何か月か経つと、遅くなったり時間切れになったりするおそれがある
- 状態: 未修正。様子を見て、署名を別の表に分けることを検討する

### 4. 本番の学生の在留期限と生年月日が空
- 場所: STUDENTS の permission_expires と birth_date（本番の60人全員）
- 影響: 許可期限切れの判定と未成年の判定が働かない
- 状態: データの入力待ち（コードの不具合ではない）

- 本番の学生の言語が全員 ja（母語で表示されていない可能性）
- まとめて締めるとき、その月に在籍していない学生を飛ばさない（コードのコメントと食い違う）（src/Admin.js）
- シートに日付型のマスが混じると判定が壊れる。起きるのは表を直接編集したときだけ（src/Db.js）
- クラスの一覧・追加・削除が書き込みの順番待ちの外で書く（同時に操作したときだけ）【曖昧】
- 先頭が「'」の値は「'」が消える【曖昧】
- まとめて締める確認の文がおかしい: 「3人を締め。」「締めしました」（src/client_js.html）

- まとめて操作のボタンが灰色で、押せないように見える
- 日本語以外の画面でもエラーの区切りに「、」「：」が混ざる
- 署名を書いた直後すぐに「決定」を押すと、1回目が効かないことがある【曖昧: 実機では未確認】

- 長期休業が1件も登録されていない（全期間が週28時間で判定される。厳しい側なので安全）
- 使っていない古いシート（WORKPLACES・MINIMUM_WAGES）と列（estimated_salary）が残っている

## 問題なし

### サーバー
- 学生は自分のデータしか読み書きできない（学籍番号はログイン情報からだけ取る）
- 管理者用の窓口と印刷は、学生のログインでは使えない
- 短い番号（K/S＋下2桁）が2人に当たるときは通さない。本番では重なりなし（国際30人、総合30人）
- 保存・確定・締める・再開は、順番待ちの中で版を照らし合わせる。古い画面からの上書きは止まる
- 自動確定は、入力済みの月や修正許可中の月を書き換えない
- 署名の長さは1マスの上限（5万字）に収まる
- 休憩（6時間以下0分、8時間以下45分、それ以上60分）、日をまたぐ勤務、週28時間の計算は仕様どおり
- 締切と修正許可の判定、日本時間、月の境目（年末・うるう年）は正しい
- 自動テスト 367件すべて合格

### 画面と印刷
- 既存の通し確認（e2e-browser.js、qa-robust-browser.js）は2つとも合格
- 7言語とも、ログイン・本人確認・学生画面・署名画面で画面のエラーは0件。文言の抜けもない
- 勤務先が空だと、署名画面を開かずに知らせる
- 署名画面は幅 320・375・390・412・横向きで「決定」が画面に収まる。指で書ける
- 学生画面とログイン画面は、どの幅でも横にはみ出さない
- 時刻の入力は「2140」「２１：４０」なども整形される。15分刻みでない値は赤枠になる
- 「決定」の連打でも、確定は1回だけ送られる
- 管理画面のチェック欄とまとめて締めるは、スマホの幅でも使える
- 印刷は1人1ページ。勤務先と署名が出る
