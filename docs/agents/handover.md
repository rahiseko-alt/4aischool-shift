## 2026-10-15 本人確認・確定ボタンのみ・自動確定を main に取り込んだ（PR #20）

**決めたこと**

- 確定済の札は、表を直し始めたら未確定にする。学生画面は確定ボタンのみで、管理者の一覧と印刷から「下書き」を出さない（既存の下書きは確定済として見せる）
- ログイン後に氏名とクラスを出して YES/NO（NO はログイン取り消し。記録しない）。ただし画面が印を付けたときだけ効く（変更禁止の既存テストがそのまま使うため）
- 締切後の自動確定の処理 `autoConfirmMonths` を追加（確定済（本人未入力）。見分けは確定日時が空）。時間で動かす登録は、実行が拒否されたため未実施で、いまは手で実行しない限り動かない
- 変更禁止ファイルのうち `CONTEXT.md` と `test/rules.test.js` を、利用者の許可のうえで更新し、照合値を作り直した

**次にやること**

- 自動確定を毎月1日の1時に動かす登録（`installTriggers` への追加）をしてよいか、利用者に決めてもらう。登録するなら、本番の Apps Script で `installTriggers` を一度実行する。最初の実行で、締切を過ぎた未入力の月（いまの本番は 2026-10 分）が一度に確定される
- 規約書 `docs/impl/INSTRUCTIONS.md` に新しい関数 `api_confirmIdentity`・`autoConfirmMonths` とエラーコード `IDENTITY_REQUIRED` を載せるか決めてもらう（変更禁止のため許可と照合値の作り直しが要る）
- main に取り込んだ変更を、本番の Apps Script へ反映する（反映の手順はこの置き場所では未確認）
- 学校に、長期休業の前後の週の28時間の扱いを確認してもらう

**未解決の問題**

- 月末以外に締切を決めた月は、自動確定が次の1日になるまで反映されない
- 本人確認は、パスワードで入る経路の学生には挟まない
- 1日に3回の勤務が全日に入るような極端な月は、印刷が2枚目に続く（切れはしない）
